# ADR 0002: pg (runtime dependency, api/)

Status: accepted for M5a. Date: 2026-11-13.

**Decision.** Use `pg` (node-postgres) with parameterized queries and no ORM.

**Why.** The API's only job is to run fixed SELECTs inside a transaction that sets the Postgres role and session claims (`SET LOCAL ROLE`, `set_config(..., true)`). An ORM would hide that transaction and add a query layer between the API and the RLS policies.

**Alternatives.** An ORM or query builder (more surface, no benefit for fixed read-only queries); `postgres` (porsager) library (smaller community, same function).

**Risks.** String-built SQL would bypass parameter binding. Mitigation: every value is bound as a parameter; the role name comes from a fixed allowlist; the leak test matrix includes SQL-looking inputs.
